# 外部接口接入实施计划

**目标：** 七个店铺平台、支付宝商家转账和企业微信群通知使用客户自己的授权完成真实接入。

**设计：** `docs/superpowers/specs/2026-09-24-external-integrations-design.md`

## 阶段一：本地安全与真实状态

1. 扩展 `db.py` 的敏感字段加密范围，覆盖电商应用密钥、店铺令牌和群机器人 URL；确认列表接口只输出遮盖值，编辑表单留空表示保留旧值。
2. 修改 `api/extra.py`、`api/system.py`、对应模板和 JS，移除原平台默认 AppId、原平台购买链接及写死的调用量。保存配置只表示“待授权”。
3. 增加服务状态面板与操作记录，未提供客户授权时明确显示未配置。

## 阶段二：企业微信群机器人

1. 增加官方域名校验、限时 POST、响应检查和错误记录。
2. 将后台“发送群消息”操作和订单发布流程接到服务端发送器，使用事件/订单/配置组合键防重复发送；失败不影响订单状态。
3. 保存规则时验证 Webhook，列表不回传完整 URL。

## 阶段三：七平台电商

1. 取得客户阿奇索应用及七平台官方接口文档，锁定每个平台的订单查询、发货、权限检查和配额接口。没有文档的调用不实现猜测版。
2. 增加阿奇索签名客户端、服务端域名白名单、超时和规范化订单模型。
3. 将 `/OrderAjax/ReadTaobaoOrderData` 与各平台读取入口接到真实店铺；本地订单状态流按平台能力提交发货任务，记录官方回执。
4. 授权到期、权限不足和接口失败均保持原订单数据可追溯，并在设置页准确显示。

## 阶段四：支付宝在线结算

1. 取得客户已上线并签约商家转账产品的应用参数，核对当前官方产品接口。
2. 增加服务端签名、验签、唯一商户单号、转账查询和账单状态机。
3. 将现有在线结算入口改为先确认付款明细，再由有权限的操作员发起；未配置商户时继续使用线下结算。
4. 支付宝明确返回最终成功后才将账单标记已支付；超时先查询，不盲目重试。

## 交付检查

逐项检查配置显示、权限不足、超时和真实平台回执；客户授权/正式 HTTPS 域名缺失的项目标记为“待客户配置”。不运行真实打款或收费接口来充当空账户验证。

## 当前实施进度（2026-09-24）

- 阶段一：已完成敏感字段加密、列表脱敏、原平台 AppId 与固定调用量清理、真实待联调状态。
- 阶段二：已完成企业微信群官方 Webhook 发送器、订单新增与状态变更触发、结果记录及手动失败重试；需客户 Webhook 才能进行真实收消息联调。
- 阶段三：已完成七平台配置入口和阿奇索通用签名函数；订单查询、发货与推送依赖客户开通权限和完整接口文档，当前保持未启用。
- 阶段四：已移除假授权与假在线交易号，关闭在线打款入口；真实结算依赖客户支付宝商家转账应用、当前产品文档及密钥，当前保持未启用。
