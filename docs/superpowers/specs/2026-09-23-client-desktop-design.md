# 客户端 PC 端全流程设计

## 目标

为现有客户客户端 `/app/` 完成适合桌面浏览器使用的全流程界面，覆盖访客浏览、注册登录、商品选择、下单、订单跟进和个人账户功能。保留当前手机端行为与视觉布局；PC 和手机共用现有 Vue 路由、接口、数据和业务规则。

本项目的“PC 端”指客户端买家侧，不包含后台员工管理系统。

## 现状

- `static/app/app.js` 已包含客户端所有路由，并按 960px 断点显示桌面顶栏或手机底部导航。
- `static/app/pages.js` 和 `pages2.js` 包含首页、游戏与商品、订单、账户、权益、消息等页面组件。
- `static/app/app.css` 已有桌面页宽、8 列游戏网格、4 列商品网格、标题和双栏容器等基础样式。
- 页面组件仍主要按手机纵向卡片流构造。桌面模式目前大多只是增宽和增加网格列数，缺少页面级的信息分组、筛选区、辅助栏和桌面操作密度。

## 方案

采用同一套路由和业务组件的响应式桌面适配层，不另建 PC 专用业务副本。基于现有顶部导航、`desk-cols`、`desk-title` 等桌面结构为各路由增加清晰的桌面内容分区；桌面特有布局用 CSS 断点与少量语义化 class 控制。只有在现有组件确实无法表达桌面信息层级时，才引入局部展示组件，不复制 API 调用、校验或状态变更流程。

### 全局框架

- 960px 及以上显示品牌、主导航、搜索入口、订单入口和账户菜单；当前路由对应的导航状态明确。
- 内容主列居中并使用可伸缩最大宽度；超宽屏增加留白，不让主要文字行无限变长。
- 登录、注册继续使用无导航的专注布局；已登录用户菜单仍提供个人中心和退出等现有操作。
- 菜单、弹层和固定操作区不得遮挡主要内容；键盘焦点和可点击区域保持清晰。
- 959px 及以下沿用当前手机布局，不更换手机导航、不删除现有移动交互。

### 页面布局

| 页面组 | 路由 | PC 布局 |
| --- | --- | --- |
| 首页与发现 | `/`、`/news`、`/news/:id`、`/boosters`、`/search` | 有明确主次的欢迎/活动区；首页游戏、热门商品与公告使用桌面网格；搜索和打手列表使用宽屏结果网格。 |
| 游戏与商城 | `/games`、`/game/:id`、`/shop`、`/item/:id` | 游戏与商品采用多列卡片；商城筛选与搜索集中在工具栏；详情使用媒体/介绍主列和价格、规格、下单摘要侧栏。 |
| 报价与下单 | `/calc`、`/order/new` | 表单按步骤和主题分组；宽屏下将输入表单与价格/订单摘要并列；摘要随页面滚动保持可见但不遮挡页脚。 |
| 订单 | `/orders`、`/order/:oid`、`/order/:oid/chat`、`/aftersales` | 订单列表提供桌面筛选栏与易扫描的行/卡片；订单详情把状态、金额和操作置于显眼位置；消息会话在宽屏中使用对话区与订单摘要分栏。 |
| 账户与权益 | `/me`、`/profile`、`/fees`、`/coupons`、`/notices`、`/points`、`/lottery`、`/roles`、`/invite`、`/levels` | 个人中心以账户摘要和功能导航构成两栏；各明细页使用合适宽度、分栏或列表布局，表格只用于可比较的明细数据。 |
| 帮助与认证 | `/faq`、`/contact`、`/agreement`、`/privacy`、`/login`、`/register` | 帮助和法律文本限制阅读行宽；联系表单置于稳定主列；登录注册使用桌面居中卡片并保留原流程。 |

所有视图仍使用当前接口返回值、错误提示、空态、加载态、登录拦截、金额计算和表单规则。设计适配不改变订单状态流、支付选项或客户数据语义。

## 断点与视觉规则

- `>= 1280px`：使用完整宽屏主列/侧栏布局和较宽商品网格。
- `960–1279px`：顶部导航保留，侧栏缩窄或在空间不足时折叠到内容下方；确保无横向溢出。
- `< 960px`：完全维持现有手机模式。
- 断点由 CSS 管理；若 JS 需要判断桌面专属交互，必须监听 `matchMedia` 变化，不能只在启动时读取窗口宽度。
- 遵循现有颜色、圆角、组件和暗色模式变量；PC 风格以现有浅色品牌方案为基准，不另引入 UI 框架或组件依赖。

## 文件范围

- `static/app/app.css`：桌面设计规则、网格、表单、表格、筛选区、辅助栏以及必要的暗色模式适配。
- `static/app/app.js`：只在必要时调整桌面全局导航/账户菜单结构；保留路由和登录逻辑。
- `static/app/pages.js`、`static/app/pages2.js`：逐页加语义化桌面布局结构或 class，复用现有数据和操作方法。
- `README.md`：实现完成后更新客户端 PC 功能说明与访问方式。

不修改 Flask API、数据库结构或后台管理端。若实现中发现任何页面缺少完成该流程所需的 API 能力，先记录缺口并暂停该页面范围变更，避免用展示层伪造功能。

## 验收标准

1. 所有 `app.js` 中定义的非回退路由都能在桌面断点正常进入并完成现有操作。
2. 浏览、搜索、筛选、详情、报价、下单、登录/注册、查看订单、联系/评价/售后、账户信息与权益页面均有适合宽屏的信息组织；不只是把手机卡片放大。
3. 订单详情、下单页和商品详情的关键摘要与主要操作在桌面首屏容易找到；侧栏在长内容场景下不遮挡或覆盖表单控件。
4. 页面具备有意义的加载、空数据、接口错误、未登录和表单校验反馈，沿用当前实现。
5. 1366px、1024px、960px 桌面宽度下无页面级横向滚动；959px、390px 下手机导航和操作不回归。
6. 主要交互可用鼠标和键盘完成；当前亮色/暗色主题在桌面下均可读。
7. 不引入重复的业务请求、重复数据源或新的前端依赖。

## 验收方式

实现后按路由组逐项检查，重点覆盖访客、已登录客户、空列表和有订单等状态；在上述桌面及手机视口下检查导航、横向溢出、固定/粘性区域、弹层、主题和主要操作。运行项目已有的客户端相关流程测试，并在浏览器做桌面和手机端交互检查；测试或浏览器验证未实际完成的项目需在交付说明中标出。

## 风险与决策

- 当前 PC 样式已有 960px 桌面导航，重做布局时必须校对所有路由的选中导航和嵌套路由返回行为。
- 手机与 PC 共用模板会让过度桌面化的 CSS 影响窄屏，因此所有桌面样式必须受桌面断点限制。
- 订单、支付、抽奖、消息等行为依赖现有后端；PC 版只复用其现有能力，不表示尚未接入的外部服务在 PC 上可用。
